# Narration

## Current voice (chosen by the user)

A synthetic deep, warm, middle-aged British documentary narrator ("voice A").

- `episodes/russia/voice_ref.wav` is the reference clip. It was made once by Qwen3-TTS **VoiceDesign** from
  `NARRATOR_DESIGN` in make_vo.py, so no real person is cloned. Reuse this same clip for every episode so the channel
  keeps one voice.
- Every line is generated by Qwen3-TTS **Base** cloning that clip (ICL mode, `ref_text` = `VOICE_REF_TEXT`).
- **Emotion:** the Base model has no public `instruct` argument, but its `model.generate` accepts `instruct_ids`. make_vo.py
  patches it, passing the line's direction from delivery.txt. Measured on a speaker embedding, voice similarity stays
  0.98–0.99 to the reference, and pitch spread on an "excited" line rises from 2.6 to 6.3 semitones.
- **`NARR_CHAIN`** is baked into each scene wav: highpass, +2 dB at 150 Hz, +2 dB at 3 kHz, de-esser, 3:1 compression,
  loudnorm to −16 LUFS. Don't add another voice EQ at mastering.

## Commands (after scripts/setup_env.sh)

```
QW=$SCRATCH/qw/bin/python    # qwen-tts + faster-whisper + librosa
TTS=$SCRATCH/tts/bin/python  # faster-whisper (timing)
VO_BATCH=2 $QW episodes/<slug>/make_vo.py qwen            # all scenes, resumable
VO_TAKES=3 $QW episodes/<slug>/make_vo.py qwen hook       # best-of-3 for listed scenes
$TTS episodes/<slug>/make_vo.py timing                    # per-line word timing -> timing.ts
```

The cache key is `sha1(spoken text + "|" + direction)`. Changing a line's direction regenerates only that line. Delete
that line's cache file to force a new take.

## QA built in

- Whisper base.en transcribes each take and compares it with the script, ignoring number words; a take passes at a score ≥ 0.86.
- Pace must be 1.7–4.2 words/s, except for lines under 4 words.
- A failing take is retried 3 times, then the last take is kept. Always read the transcripts of kept-but-flagged lines.
  Usually it's digits ("1480" for "fourteen eighty"), roman numerals ("Ivan III") or foreign words.

## Speed and limits (4 CPUs, 16 GB)

- About 7× real time batched, 11× single. A 12-minute script takes roughly 80–90 minutes.
- Batch 4 on long lines needs more than 14 GB and gets OOM-killed. Use `VO_BATCH=2`.

## Alternatives that were tried

| Engine | Verdict |
|---|---|
| Kokoro am_onyx (0.8×) | Deep but flat and robotic; the user rejected it. Fast, Apache-2.0. |
| Kokoro bm_george | British, still flat. |
| Chatterbox (MIT), cloning voice A | Good emotion via `exaggeration`. A fine fallback; similar quality to Qwen + directions. |
| Qwen3-TTS CustomVoice Ryan / Aiden | Decent stock voices; Aiden is the most expressive. Uses about 4.3 GB of disk. |
| ElevenLabs (paid API) | What most competitor channels use (Adam, Brian, George, etc.). The user would need a key. |
| Fish Audio API (paid) | User's suggested upgrade for the hook. Clone voice A there to keep one narrator. Open weights are non-commercial: don't use them. |

## Comparing voices with the user

You can't hear, so measure, then let the user listen:

- Generate the same 2–3 lines with each candidate.
- Normalise each to −16 LUFS.
- Build one video with a big letter card per voice (ffmpeg `drawtext` with the Oswald font, an explicit `-t` duration,
  never `apad` + `-shortest`).
- Send it, then ask with AskUserQuestion.
